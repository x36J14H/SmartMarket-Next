## 7. Каталог: фильтры, пагинация, сортировка

**Реализовано:**
- **Трёхуровневая иерархия** категорий: категория → подкатегория → тип. URL-маршрут: `/catalog/[cat]/[sub]/[type]`
- **Фильтр по брендам** — чекбоксы, мультивыбор через query-параметр `?brand=slug1,slug2`
- **Пагинация** — постраничная, 20 товаров на страницу (`PAGE_SIZE = 20`), параметр `?page=N`. Отображаются кнопки с эллипсисом для длинных диапазонов
- **Переключение вида** — сетка (grid) / список (list)
- **Отмена запроса** — `AbortController` при смене фильтров
- **Счётчик результатов** — «Найдено: N товаров»

**Не реализовано:** сортировка, бесконечная прокрутка (используется классическая пагинация).

## 10. Корзина

**Реализовано:**
- **Добавление** — с карточки товара и страницы товара, оптимистичное обновление UI
- **Изменение количества** — кнопки +/−, ограничение по `inStock`
- **Удаление** — отдельного товара или всей корзины
- **Выбор позиций** — чекбоксы для каждого товара, «Выбрать все», удаление выбранных
- **Сумма** — пересчитывается по выбранным позициям (или по всем, если ничего не выбрано)
- **Синхронизация с 1С** — все операции дублируются на сервер через `personalService` (POST/PATCH/DELETE `/api/personal/cart/{id}`)
- **Откат при ошибке** — если запрос к 1С упал, состояние возвращается к предыдущему
- **Гостевая корзина** — сохраняется в `localStorage` через `zustand/persist`. При входе — `mergeToServer()` заливает гостевые товары в аккаунт
- **Мобильная плавающая панель** — появляется когда кнопка «Оформить» уходит из viewport (IntersectionObserver)

## 12. Авторизация на фронтенде

**Схема:**
1. Пользователь вводит email/пароль в `AuthModal`
2. Запрос уходит на `POST /api/auth/login` (Next.js Route Handler)
3. Route Handler проксирует запрос в 1С (`ONEC_AUTH_URL/login`) с Basic Auth
4. 1С возвращает JWT-токен
5. Route Handler устанавливает **httpOnly cookie** `auth_token` (недоступна из JS)
6. Фронтенд запрашивает `GET /api/auth/profile` — Route Handler читает cookie и проксирует в 1С
7. Профиль сохраняется в Zustand (`useAuthStore`)

**Ключевые решения:**
- Токен хранится только в httpOnly cookie — защита от XSS
- Учётные данные 1С (`ONEC_USERNAME`, `ONEC_PASSWORD`) — только на сервере, в env-переменных
- `AuthProvider` — Client Component в корне layout, при монтировании проверяет сессию через `/api/auth/profile`
- Нет middleware Next.js для защиты маршрутов — защита реализована на уровне компонентов (редирект в `useEffect`)

## 13. Server Actions для форм входа/регистрации

**Не используются.** Формы входа и регистрации работают через обычные `fetch`-запросы к Route Handlers (`/api/auth/*`). Это сознательное решение: Route Handlers дают больше контроля над установкой cookies и обработкой ошибок.

---

## 14. Истечение токена и обновление сессии

- Токен устанавливается с `maxAge = expires_in` (значение из ответа 1С, по умолчанию 30 дней)
- При истечении cookie браузер автоматически её удаляет
- При следующем запросе `GET /api/auth/profile` вернёт 401 → `AuthProvider` вызовет `setUser(null)` → Zustand сбросит состояние
- **Автоматического обновления токена (refresh token) нет** — при истечении пользователь должен войти заново

## 16. Оптимизации производительности

| Оптимизация | Реализация |
|---|---|
| **AbortController** | Отмена незавершённых fetch при смене параметров (каталог, поиск, карточка) |
| **Оптимистичные обновления** | Корзина и избранное обновляются мгновенно, откат при ошибке сервера |
| **Lazy loading изображений** | `next/image` с `fill` и `sizes` — автоматическая оптимизация |
| **Кэширование изображений** | Прокси `/api/1c` устанавливает `Cache-Control: public, max-age=2592000, immutable` для изображений товаров |

| **Анимации через GPU** | `motion/react` использует CSS transform/opacity — не вызывает reflow |

## 18. Запросы к HTTP-сервисам 1С

**Архитектура прокси:**

```
Браузер → /api/1c/[...path] → 1С HTTP-сервис
Браузер → /api/personal/[...path] → 1С HTTP-сервис (личный кабинет)
Браузер → /api/auth/* → 1С Auth HTTP-сервис
```

**Переменные окружения:**
- `ONEC_BASE_URL` — базовый URL публичного API 1С
- `ONEC_AUTH_URL` — URL сервиса авторизации 1С
- `ONEC_USERNAME`, `ONEC_PASSWORD` — учётные данные для Basic Auth

**Обработка ошибок:**
- Таймаут 15 сек для каталога, 10 сек для личного кабинета (`AbortSignal.timeout`)
- При ошибке сети — `502 Bad Gateway` с текстом ошибки
- Защита от SSRF в прокси каталога: разрешены только пути `catalog`, `categories`, `brands`
- Изображения кэшируются на 30 дней

**Базовый клиент (`lib/1c/client.ts`):**
```typescript
const onecClient = {
  get: <T>(path: string, signal?: AbortSignal) =>
    request<T>(path, { signal }),
};
```
Все запросы идут через `/api/1c` — учётные данные 1С никогда не попадают в браузер.

## 19. Гибридный поиск (AI + 1С)

**Реализован** в `app/api/ai-search/route.ts`:

```
1. POST /api/ai-search { query, limit }
2. Попытка семантического поиска → AI_SERVICE_URL/api/v1/products/search (таймаут 5 сек)
   ├── Успех → возвращает { ids, source: 'semantic' }
   └── Ошибка/таймаут → Fallback
3. Fallback: текстовый поиск через 1С → ONEC_BASE_URL/catalog?q=...
   └── Возвращает { ids, source: 'text' }
```

Сервис `services/aiSearch.ts` получает список UUID от `/api/ai-search`, затем загружает полные данные товаров через `/api/1c/catalog/{id}`.

Дополнительно реализован **AI-чатбот** (`AIChatbot.tsx`) на базе Google Gemini API — отвечает на вопросы о товарах в формате чата.

## 20. Остатки товаров в реальном времени

- Остаток (`inStock`) приходит в каждом ответе API 1С при загрузке товара
- На карточке товара отображается: «В наличии: N шт.» или «Нет в наличии»
- Кнопка «В корзину» блокируется при `inStock === 0`
- При добавлении в корзину количество ограничивается значением `inStock`: `Math.min(quantity, inStock)`
- **Реального времени (WebSocket/polling) нет** — данные актуальны на момент загрузки страницы

## Дополнительные заметки для написания текста

### Что стоит подчеркнуть:

1. **Архитектурное решение с прокси** — Route Handlers скрывают учётные данные 1С и решают CORS. Это стандартный паттерн BFF (Backend for Frontend).

2. **Оптимистичные обновления** — корзина и избранное реагируют мгновенно, без ожидания ответа 1С. При ошибке — автоматический откат. Это улучшает UX при медленном соединении.

3. **Гостевой режим** — корзина и избранное работают без авторизации (localStorage). При входе данные автоматически переносятся в аккаунт 1С.

4. **Трёхуровневая иерархия каталога** — отражает структуру справочника номенклатуры 1С (группа → подгруппа → вид).

5. **Типобезопасность** — строгий TypeScript, типы API 1С (`ApiProduct`, `ApiCatalogResponse`) отделены от типов UI (`Product`). Маппинг в `catalog.ts`.

### Что честно признать ограничениями MVP:

- Нет SSR/SSG для страниц товаров (все Client Components) — влияет на SEO
- Нет refresh token — при истечении сессии нужен повторный вход
- История заказов — mock-данные, интеграция с 1С не завершена
- Страница оформления заказа не реализована
- PWA не реализован
- Нет сортировки товаров в каталоге
